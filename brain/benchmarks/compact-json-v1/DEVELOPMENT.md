# Development r1 plan

The development run compares all four JSON factorial cells and the separate
native MIDI-like anchor on 20 fresh progression fixtures. It reserves 20
different progression fixtures for a later targeted holdout.

Each provider has 100 isolated calls. Run OpenAI and Gemini first. Run Claude
only when the two providers disagree on a frozen decision signal.

The JSON hierarchy first tests tuple shape at both pitch encodings. Tuple must
stay within a 5 percentage-point paired non-inferiority margin and pass the
structural compactness gate. The hierarchy then retains pitch-class/register
only when pitch-critical accuracy improves by at least 5 percentage points on
two providers without a larger primary regression.

A material interaction can freeze more than one eligible JSON cell for
holdout. Native MIDI-like remains outside the factorial. It can enter holdout
only as a limited-interface candidate on common musical metrics.

Every provider request uses 5,000 output tokens. The deterministic screen
checks the exact request payload. The operator must approve the frozen plan
before any development call.
