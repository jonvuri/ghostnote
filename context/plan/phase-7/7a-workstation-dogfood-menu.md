# Phase 7a — Workstation dogfood menu

## Menu

Use one fresh projectless session for each selected item. Supply the musical
content and exact acceptance criteria at run time.

1. **Hybrid preset orchestration.** Retry the three-voice Repro-5, Diva, and
   bass request. Use computer use for preset browsing and the Bitwig adapter for
   structure, composition, and independent readback.
2. **Audio-guided sound design.** Make controlled parameter changes, capture
   matched snippets, compare deterministic and perceptual results, and wait for
   the operator's aesthetic verdict.
3. **Documentation-guided construction.** Answer one Bitwig workflow or native
   device question from exact-version offline sources, then use the result in a
   real patch without web search.
4. **Theory-guided composition and revision.** Create a clip block, analyze its
   harmony, rhythm, register, and voice leading, apply one constrained semantic
   transformation, and compare the before and after reports.
5. **Clip composition and revision.** Create a clip from a musical brief. Read
   it back, transform it, change metadata and launch behavior, and audition it.
6. **Long asynchronous composition.** Generate a long or dense clip, inspect
   progress, revise it after completion, and cancel only when the musical task
   calls for it.
7. **Drum Machine production.** Build a multi-pad kit and beat, change nested
   device parameters, copy a variation, and audition both clips.
8. **Device-alternate audition.** Create several alternatives for one device,
   switch them, compare matched audio snippets, and keep one explicit choice.
9. **General parameter sound design.** Use a native, VST3, or CLAP device.
   Inspect direct and remote controls, set continuous and discrete values, and
   use computer use only for semantic UI controls that Ghostnote cannot express.
10. **Preset modulation editing.** Inspect a saved preset, then add, retarget,
    resize, replace, and delete supported modulators. Require exact live page and
    behavior readback.
11. **Layered source composition.** Build an Instrument Layer or FX Layer from
    native, plug-in, preset, and existing-device sources. Include nested
    modulation and an explicit keep-or-reverse verdict.
12. **Launcher and project structure.** Add and rename an owned track, add
    scenes, create a small clip block, move or copy it, and remove only rejected
    owned content with exact change checks.

## Cross-run questions

- Did the workstation remove slow UI work or add ceremony?
- Which verification step found a real defect?
- Which verification step repeated already sufficient evidence?
- Did each module work independently when another module was absent?
- Did an established external tool outperform a custom component?
- Was the final claim supported by the stated evidence source?

## Required result

Record the root session, client, model, reasoning effort, workstation and tool
versions, Bitwig and host API versions, project baseline, enabled modules,
operating mode, writes, external UI changes, captures, evidence labels, timing,
operator verdict, and exact exit state.
