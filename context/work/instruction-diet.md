# DIET — Reduce instruction and artifact load

**Item:** [DIET](../BACKLOG.md). Keep instructions and references that have a
current use supported by evidence. Reduce required reading, repeated records,
and inherited prescriptions that add work without improving the result.

## Scope and acceptance

Apply the user's review of 2026-10-24/25: preserve justified outcomes, not every
existing mechanism called a protection. DIET changes the documentation that
leads to implementation choices. [P01](../plan/overlap/wave-4/work-sessions.md#p01--edit-path-performance-and-recovery-cost)
examines existing runtime checks and recovery costs. V10 evaluates its proposed
mechanisms when implementing them.

- Shorten AGENTS and the context guide. Allow small tasks without a brief,
  separate E record, or retrospective. Keep a short optional brief example.
- Apply D54 to current plans and contracts. Distinguish correctness, result
  evidence, and recovery. Preserve operator procedures, D15 readback, D52
  admission, truthful effects, and relevant cleanup. Keep public behavior
  until an implementation updates it and its contract together.
- Keep useful measurements, technical plans, manifests, runbooks, and wave
  evidence. Scope reading to the selected work. Retire obsolete execution
  instructions and status cues selectively; retain stable historical links.
- Keep call-budget checks and relevant cost measurements. Replace repeated
  model essays with concise path references and archive the earlier ledger.
- Update capability summaries when their interpretation changes. Use separate
  E records for durable measurements that need citation or reproduction,
  including offline results. Keep earlier E/D records unchanged.
- Make frontmatter optional and remove the closed Phase 1 status check. Keep
  local link checks. Check changed anchors and archive links separately.
- Stage the changes and obtain an independent agent review. Judge success by
  reduced routine reading and maintenance with useful knowledge intact.

## Evidence checked

had 1,085 words; the guide had 1,122; the ledger had 22,926. There were 262
plan files, 55 marked active/planned. The earlier wave-4 snapshot had 61.
That set included evidence, a symbol manifest, and a runbook, so status alone
was not a reason to archive it.

The ledger had 17 model headings, not 15. There were 391 experiment Markdown
files; the latest 60 by filename had a median of 1,108.5 words. Wave 4 had
18 files and about 17,300 Markdown words. The original required-reading and
hedge-density figures lacked a defined counting method; they were not used
as acceptance measures. Size and formal language alone do not establish waste.

The checker failed on 18 missing YAML headers, separate from its obsolete
Phase 1 rule. The maintenance rules also required repeated tool counts and
publication snapshot updates for routine edits. V10 required the full source
list and an E record for every sub-session. These were concrete sources of
repeated work.

## Result

The central instructions now use a small work loop and retain the live operator
procedure. The guide separates current policy, reference data, and historical
instructions. The optional [template](TEMPLATE.md) illustrates a short brief.

The ledger keeps measured product costs and concise Grid references; its
[prior body](../archive/performance-ledger-2026-10-24.md) and old model anchors
remain available. V10 keeps its technical design and functional acceptance,
while paired captures/readbacks and pre-disconnect are proposed mechanisms to
assess against evidence. P01's scope remains runtime analysis.

Migration and interface references identify historical gates. PROJECT owns the
current tool count; other inventories retain dated snapshots. Publication
inventory refresh belongs to a REL candidate review. Capability pages retain
source attribution without requiring tags or new probes for every observation.
Plan entry points now route obsolete phase work to the backlog. Useful source
files remain at stable paths. No runtime, tool description version, E/D record,
wave-3 data, or live project changed.

Verification passes: the context link check, diff whitespace check, and 84
changed or incoming Markdown anchors, including archive links. Temporary
checker fixtures confirm that plain Markdown needs no frontmatter or Phase 1
tree, broken file links still fail, and the archive exclusion remains.
The first independent review checked live procedures, D54 scope, historical
links, and preservation of the prior ledger body. A later review found stale
capability instructions and wave-4 status text, a missing template route, and
imprecise E15-F and D54 wording. These are corrected, along with line wrapping.
The correction link, anchor, and diff checks pass. Historical status metadata
remains as agreed.
AGENTS is 480 words (was 1,085), the guide 507 (was 1,122), and the current
ledger 6,767 (was 22,926). DIET is closed; V01 is next.
