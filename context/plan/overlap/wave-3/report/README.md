# Static synthesis report

Open [report.html](../report.html) in a browser. The file contains all content,
styles, and filter logic. It works from a local file without a server. Evidence
links use repository-relative paths or exact external source commits.

The report gives every work record a disposition. It retains all Ghostnote
and external cells with their full source fields. Status and proof remain
separate. Empty cells and Not found have different meanings. Source options,
workflow summaries, effort drivers, and sequence tradeoffs are editorial
synthesis; their links lead to the supporting records. They are not measured
estimates or accepted priorities.

## Matrix layout

The external matrix keeps Ghostnote first. It sorts other projects by the
number of recorded capability cells, excluding Not found. Ties use project
name. Counts include Source and Claim evidence; they are not counts of passed
checks or a measure of total project breadth. Vertical headers and separate
verb and proof lines let all columns fit at 1280- and 1440-pixel desktop
widths. Smaller screens keep horizontal scrolling inside the matrix.

The records have no verb-applicability field. Ghostnote dashes therefore
remain “no standing recorded.” They cannot reliably distinguish N/A from
unmeasured behavior. No applicability claim was added.

## Build

`template.html` holds the presentation and synthesis. `build.py` reads
`../data/records.json` and inserts matrices, record details, counts, source
pins, and typed dependencies. It uses only the Python standard library. The
build runs the input validator first.

```sh
python3 -I context/plan/overlap/wave-3/report/build.py
python3 -I context/plan/overlap/wave-3/report/build.py --check
ruby context/check.rb
```

The check compares the generated bytes, checks every record and cell ID,
checks local links and internal anchors, and confirms the description count
and version. External links are derived from the retained pin manifest; the
check does not make network requests.
