## Build

`scope.json` records proposed dispositions for all 58 baseline work IDs.
`build.py` joins it to wave-3 records. Titles, owners, status, and proof come
from that baseline. `coverage.json` assigns all 76 rows to 25 functional
groups. Each group states a proposed case and its limit. The generated table
links all original Ghostnote and external cells without changing their proof.
`sequence.json` defines 13 working variations, their dependencies, acceptance,
work IDs, and research briefs. The builder validates these references and
generates the sequence table. Coverage groups carry priority and case links.
`report-template.html` supplies the visual explanation.
`report.html` contains all report data and works without a server. JavaScript
only filters the view. Without JavaScript, all content remains available.

```sh
# ruby needs a UTF-8 locale: LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
python3 -I context/plan/overlap/wave-4/build.py
python3 -I context/plan/overlap/wave-4/build.py --check
python3 -I context/plan/overlap/wave-3/report/build.py --check
ruby context/check.rb
git diff --check
git diff --cached --check
```

The build check requires all baseline IDs exactly once, a reason and
disposition for each record, matching generated bytes, unique HTML IDs,
local report links, and HTML anchors. The source hash is in the report.
It also requires each of the 76 capability rows exactly once, valid workflow
names, a priority, case and limit for each coverage group, and valid baseline
cell links. All 13 variation IDs must be unique, dependencies must refer to
earlier cases, and work/research/coverage references must resolve.
Research references are R01 through R05.
The context check covers Markdown frontmatter and local link targets.
