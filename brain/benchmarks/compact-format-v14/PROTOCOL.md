## Estimands

The compact-to-compact estimand is the effect of the complete deployable
prompt package on initial strict conformance and semantic accuracy. Each
compact-to-exact estimand is initial semantic noninferiority under the complete
prompt package. Byte and token size are separate estimands.

Analysis varies only the input representation. It uses one neutral output
grammar. Affine continuation varies the input and output representation. The
serialization guard varies only the output representation and gives every
target value in neutral JSON.

Progression does not decide this holdout. Its historical task is at a reasoning
floor. Affine continuation uses the exact formula
`2*axis-source_pitch+semitones`. Every analysis batch has four cases.

## Measurement

Report these values separately:

- structural parse, canonical conformance, strict conformance, and semantic
  pass;
- strict batch pass and analysis component accuracy;
- planned, attempted, provider-completed, available, and scored denominators;
- unavailable, failed, initial, and repaired states;
- prompt bytes, response bytes, API input tokens, and API output tokens; and
- repeated response variation.

There is no repair call. The repaired state is always absent. An unavailable
or failed result is not a musical failure and does not enter a scored model-
accuracy denominator.

## Gates and stopping rule

The smallest useful paired difference is two of sixteen repeated decision
rows, or 12.5 percentage points. The noninferiority margin against exact JSON
is a pass-rate deficit of two rows per provider and family. Offset candidate
wins and losses before applying this margin. A candidate can have no fixture
on which exact JSON passes both repeats and the candidate fails both repeats.

Each provider must complete at least 95 percent of planned work. Each compact
candidate must pass strict syntax on at least 87.5 percent of its scored rows.
The exact control must pass at least 75 percent of scored rows. A decision
family is effect-eligible only when exact JSON is from 75 percent inclusive to
95 percent exclusive and at least one compact arm is strictly between 25 and
87.5 percent for that provider and family. Each provider must have at least
one effect-eligible decision family. Other families are guard results.

Return `retain-both` only when both compact candidates pass every gate. Return
`revise` for a bounded candidate, calibration, or conformance miss. Return
`stop` for an identity, freshness, preflight, cost, control-validity, or
completion failure. Do not remove a retained candidate without a later
operator decision.

Stop before paid work when identity, credentials, or network preflight fails.
During a provider run, stop on the first transport or budget failure. Retain
the raw hash, usage, cost, and provider-completed state when a received
response fails local content parsing. Stop after three unavailable responses.
Make no automatic retry. A recovery needs a new approved supplement.
