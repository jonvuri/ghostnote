## Purpose

Use the public composition tool for one useful layered patch, exercise it with
the existing parameter surface, reverse it, and close Phase 5 with one complete
audit.

## Scope

1. Define one musically useful two-to-four-entry Instrument Layer request. It
   must use at least two distinct native devices and at least two active named
   modulation routes.
2. Create the complete structure through `compose_device_structure`.
3. Use existing Phase 4 tools to set selected nested device parameters. Do not
   add parameter values to the composition schema.
4. Read back the complete container, entry order, nested device names,
   modulator pages, parameter bases, and active modulation behavior.
5. Reverse the composition change through the public reversal tool. Confirm
   that no track, device, clip, temporary file, or launcher residue remains.
6. Run the complete current public surface conformance matrix. Include the new
   composition tool and all four existing `author_modulators` operations.
7. Audit every Phase 5 exit criterion against E65 through the final composition
   evidence. Do not repeat a live case when existing evidence already proves it.
8. Record the template policy and current limits in the active decisions and
   capability documentation.
9. Correct current documentation that says layer growth is unavailable. A
   seeded live layer can grow through typed duplication. Only the file composer
   is limited to the shipped template capacity.
10. Record the final evidence and Phase 5 outcome. Mark Phase 5 complete and
    hand `context/NOW.md` to the next selected Phase 6 item.

## Policy closeout

- The Phase 5 product library contains one user-authored four-entry Instrument
  Layer template with recorded provenance.
- The required template ships with the product. There is no first-run
  generation or runtime operator setup.
- The product does not ship a copied Bitwig bundled preset.
- External redistribution review and standalone `bwmod` publication remain
  Phase 6 work.
- Growth above four entries and new container shapes need a new measured asset
  or a separately planned typed-runtime workflow.

## Acceptance criteria

- One public request creates a useful complete layered patch, not a format-only
  fixture.
- Existing public parameter tools reach and verify the nested devices without a
  new parameter grammar.
- Exact remote witnesses prove every planned active modulation route.
- The public result reports the composition change and its reversal boundary.
- Reversal reports no unrestored state and the final read-only inventory matches
  the accepted project baseline exactly.
- The full brain check, extension build and tests, deploy freshness, method-table
  handshake, live conformance matrix, and remote CI pass for one exact candidate.
- The Phase 5 overview, roadmap, decisions, capability pages, evidence index,
  outcome archive, and `NOW.md` agree on the final state and limits.

## Out of scope

- Expanding the donor or target-recipe cohorts without a dogfood need.
- A second template shape or a wider template.
- Publishing `bwmod`, the format specification, or binary assets externally.
- Any Phase 6 breadth item.

## Retrospective target

Use dogfood to test the composition vocabulary and object boundary. Do not turn
the closeout into speculative asset or target expansion.
