# Phase 4, session 4j — dogfood and closeout

> **Purpose.** Confirm that the Phase 4 surface is useful in a natural session,
> then close every criterion from exact evidence.

## Preconditions

Sessions 4a through 4i are complete. The accepted musical project and every
scratch fixture are at their documented baselines. The public description cohort
is frozen. No unresolved performance gate remains.

## Scope

1. Use the ordinary MCP surface for one natural sound-design task chosen from the
   open project. Do not script the musical or sonic judgment in advance.
2. Inspect the target chain and parameter inventories, build or adjust a useful
   multi-device chain, set several parameters by returned ids, and audition the
   result.
3. Record which result the operator keeps, rejects, or revises. Save an accepted
   result only with operator direction.
4. Run the complete scratch proof: native, VST3, and CLAP enumeration beyond
   eight parameters; independent write readback; depth-2 addressing; drum-pad
   addressing; remote controls; bypass; mixed-chain reversal; and non-taking
   write reporting.
5. Map every Phase 4 exit criterion to exact evidence and record all format,
   bank, display, automation, modulation, and fidelity qualifications.
6. Restore scratch tracks, devices, configuration, selection, and transport.
   Confirm the accepted project baseline or the explicitly saved new baseline.
7. Update the roadmap, Phase 4 overview, decisions, capability pages, evidence
   index, and `NOW.md` for Phase 5.

## Required boundaries

- Natural dogfood is not a benchmark fixture. Keep its judgment separate from
  the controlled performance evidence.
- Do not publish a plugin availability claim beyond the measured machine.
- Do not broaden the native typed cohort to make the matrix look larger.
- Do not claim that Phase 4 authors modulator topology.
- Do not leave a rejected sound-design result or scratch device in the project.

## Exit criteria

1. One natural task uses the registered public device surface and records an
   operator verdict.
2. Native, VST3, and CLAP each enumerate, name, read, write, and independently
   verify more than eight parameters.
3. A mixed FX chain is ordered, tuned, checkpointed, and exactly reversed on the
   scratch fixture.
4. Native catalog entries used in the accepted or proof workflow resolve live.
5. Depth-2, drum-pad, remote-control, modulation-warning, automation-warning,
   bypass, silent-no-op, and incomplete-window cases have explicit results.
6. All live projects and configuration files match their accepted baselines. No
   test residue remains.
7. Focused tests, full conformance, the complete brain check, extension build,
   live handshake, context check, `git diff --check`, and required remote CI pass.
8. Phase 5 receives one short, accurate handoff that names remote-control
   readback as its modulation verification instrument.

## Retrospective target

Record whether the public parameter inventory was sufficient for a natural
sound-design request. Add no speculative device-specific view.

## Result

[E63](../../evidence/experiments/e63-device-dogfood-exposes-ab-selection-gap.md)
records the accepted `Harmony – Open Minor` sound-design task. The public
inventory was sufficient. The operator kept the colder Chorus+ and Reverb
revision after a managed A/B comparison. Directed collapse restored the winning
chain to the top level and removed the alternate container.

The task exposed an A/B selection-policy gap. The factual descriptions do not
tell an agent when subjective revision language should create an alternate. E63
records the operator-accepted candidate policy as evidence only. The frozen
cohort does not change from one session.

[E64](../../evidence/experiments/e64-phase-4-closes-with-saved-device-baseline.md)
records the saved accepted chain, complete scratch matrix, final baseline,
local and live checks, and remote CI. Every exit criterion passes. The
[Phase 4 outcome](../../archive/outcomes/PHASE-4.md) is the durable closeout.
