Start with the desired result

The summaries below distinguish current tools from proposed additions. Their links lead to the exact status, proof, limits, and remaining work.

Mix and operate a session

Available now · Product

Track volume, pan, mute, solo; track and scene creation and deletion; Launcher launch. Track operations and scene operations have different limits.

Add to complete the workflow

Sends, Master, transport, Launcher stop, and cue markers. These are candidates, with source evidence.

Main choice

Mixing an existing project and live performance need different controls. The operator currently stops transport after launch.

Edit phrases and build songs

Available now · Product

Launcher note editing, clip movement and copying, and MIDI file conversion.

Add to complete the workflow

Exact Arranger reads before MIDI edits or audio edits. Automation needs its own lane and time model.

Main limit

Pressure is not observable. Full clip rewrites can lose it. Same-channel, same-pitch overlaps are refused. Recording Launcher playback is a separate option, not exact timeline authoring.

Shape and compare sounds

Available now · Product

DirectParameter and remote controls, layer and Drum Machine composition, and existing-device modulation wrapping.

Add to complete the workflow

Physical units, wider nested access, and route enabled state address different needs. Route modes and scale sources are separate extensions.

Main choice

Name a blocked sound-design task before extending all routes. Current composition, solo, and move tools already support parts of an A/B workflow; they are not atomic.

Build instruments and reusable patches

Current boundary

Grid admission is Product. Grid authoring is Planned, backed by scoped research. Preset modulation is Product.

Two distinct outputs

Phase 11 live Grid tools edit the current project. Offline Grid generation creates reusable files. The recursive codec can help file work.

Main limit

Wave one keeps existing module positions and uses 76 admitted roles. Donor-free modulation has a blocked exact-build extractor; the codec does not depend on that extractor.

Find material and evaluate results

Existing code, outside normal tools

Master capture is a Component with Live 6.0.6 proof. Audio facts is a Component with offline proof.

Add to complete the workflow

Search, sample insertion, and musical navigation solve separate tasks. The navigation survey already belongs to 8i17.

Main limit

Capture is the project master, not a stem. Audio facts have narrow input limits. Separation and transcription have no audited donor here.

Share or release the work

Existing owners

10a: bwmod package, 10b: Document 1.0 package, and 10c: release and upgrade suite are Planned.

Separate choices

Installation and compatibility, format publication, catalog distribution, and extension distribution have different owners and gaps.

Main choice

Release work can wait while personal capabilities grow. A new codec could change what 10a extracts. No package is approved for publication by this report.

Provisional direction: capabilities and speed matter more than perfect restoration. Functional equivalence is the stated requirement.

Preservation, reversal, and persistence: keep the distinctions

Preservation means that state outside the requested edit stays intact. A clip rewrite can lose pressure even when the requested notes are correct. A device move can preserve opaque state without exposing that state to a reader.

Reversal means that a recorded Ghostnote change can restore its stated prior state while guards hold. Change records belong to one server process. Persistence means that a named change survived a save and reload in a measured fixture. Neither follows from the other.

Use the revert and persist columns and the counterexample on each write or move cell. Current behavior is scoped; no single “safe” label summarizes it.

07

Decisions that change the next plan

The user’s provisional statement favours capabilities, speed, and functional equivalence over perfect restoration. The report treats that as a preference to discuss, not a change to existing decisions.

D15: verify the actual result

D15 requires input validation and independent readback. A writing cursor can echo its own cache even when the host did not apply the edit. A deferred host exception can escape the extension and crash Bitwig.

This is about knowing whether the requested edit happened and avoiding invalid host calls. It does not require every feature to have perfect reversal.

D49: state what a revert restored

D49 defines the result fields. Revert fidelity reports what returned to the prior state; redo fidelity reports what a second reversal could restore. Removed objects and unresolved parts must be named.

D49 adds no host call. It does not require universal exact reversal. A feature can have a stated lossy or missing inverse without reporting that it restored everything.

Possible contract direction, not adopted: define a bounded functional-equivalence result for a selected task, allow a stated lossy inverse where useful, and keep independent verification of that result. State which identity, metadata, automation, and sound differences matter for that task. Do not silently treat “sounds similar” as a complete state comparison.

  1. Primary outcome: choose mixing, sound design, instrument construction, song construction, or understanding reference material. Name one real task that blocks progress.
  2. Completion target: favour complete common workflows or maximum primitive coverage? A missing stop or sample insertion step can matter more than many rare controls.
  3. Live versus offline: how useful are reusable files compared with direct edits to the current project?
  4. Specific missing support: which modulator types, payloads, device routes, or media formats are needed first?
  5. Operator effort: what setup is acceptable for capture, save/reload checks, and controller replacement?
  6. Release: is outside use a near-term goal, or should personal capabilities come first?
  7. Maintenance: should internal-host features have a separate phase and compatibility budget?

Answers can select or combine the proposed sequences. No new implementation brief or accepted priority order is created here. The next decision session records those choices before planning work.
